# 订单状态标签页设计

## 目标

将运营端“我的订单”和仓储端“订单处理”的订单状态筛选，从查询表单中的下拉框改为顶部状态标签页，减少切换订单阶段时的操作次数。

## 范围

- 涉及页面：
  - `frontend/src/views/operator/OrderList.vue`
  - `frontend/src/views/warehouse/PendingOrders.vue`
- 不修改订单状态枚举、后端查询接口、订单权限或流转规则。
- 保留关键词查询、重置、分页、导出和现有操作按钮。

## 交互

1. 表格卡片顶部显示标签页：`全部`、`待接单`、`已接单`、`数量待确认`、`备货中`、`已发货`、`已完成`、`已取消`。
2. 默认选中“全部”，请求不传 `status`；其他标签使用既有状态值 `10/20/25/30/40/50/90` 请求既有接口。
3. 点击任一标签时，更新 `query.status`、将页码重置为 1，并立即刷新列表。
4. 顶部查询区域只保留关键词与“查询 / 重置”。重置恢复“全部”标签、清空关键词并重新加载。
5. 运营端导出沿用当前 `query.status`，因此导出内容与当前标签筛选一致。
6. 仓储端仍只对“待接单”订单展示“接单并关联货号”；其他状态仅保留现有详情能力。

## 组件与数据流

- 两个页面均复用 `ORDER_STATUS_OPTIONS` 生成状态标签，避免新增或复制状态枚举。
- 标签页的 `v-model` 直接绑定现有 `query.status`：运营端“全部”为空字符串，仓储端“全部”为 `null`，以保留各页面现有接口参数约定。
- 点击事件调用页面现有 `load()`；后端 `/api/sales-orders` 和 `/api/warehouse/pending-orders` 的 `status` 参数无需变化。

## 验证

- 新增前端静态交互契约测试，断言两个页面：
  - 使用状态标签页；
  - 未再渲染订单状态下拉选择器；
  - 标签切换会重置到第 1 页并调用加载方法；
  - 运营端导出仍使用当前 `query.status`。
- 执行全部前端静态契约测试与 `npm run build`。
