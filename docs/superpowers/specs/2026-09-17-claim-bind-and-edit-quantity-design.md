# 接单关联货号与运营修改数量设计

## 目标

让仓储在待接单订单的详情抽屉中连续完成接单与货号关联；全部关联后，运营可逐行修改最终出库数量。确认后系统按修改后的数量预留库存，并进入「备货中」。

## 流程

1. 仓储从「待接单」点击详情，在同一抽屉选择仓库并接单。
2. 接单成功后抽屉保持打开，立即展示每一行的关联或新建货号操作；不需要跳转「我处理的单」。
3. 所有行关联完成后，订单自动由 20「已接单」进入 25「数量待确认」。
4. 运营在订单详情的数量待确认阶段编辑每行数量；默认值为 1，每行必须为大于 0 的整数，且所有明细行都必须提交。
5. 运营确认后，后端在同一事务中校验状态、更新明细数量/小计和订单汇总，并将订单变为 30「备货中」。不校验或预留库存，库存不足由仓储在备货阶段采购处理。

## 边界与界面

- 「备货中」表示库存已按最终确认数量锁定，仓储可以拣货和发货；它不是接单后的手动中间页。
- 待接单列表的直接「接单」也会自动打开同一个详情抽屉，确保后续货号处理无需切换页面。
- 运营侧保留订单详情的原始明细展示；状态为 25 时数量列改为可编辑输入框，底部按钮文案为「确认数量并开始备货」。
- `confirm-quantity` 请求体改为 `{ items: [{ item_id, count }] }`，不再接受空对象。

## 验证

- 后端测试覆盖：合法整数数量更新会重算订单金额和总数；缺行、重复行、非正整数会拒绝；库存不足仍可进入备货中。
- 前端契约测试覆盖：仓储接单成功后保持抽屉并显示关联操作；运营状态 25 显示可编辑数量并提交 `items`。
