### 1.2 后端依赖（Python）

全部列在 `backend/requirements.txt`，一条命令装完：

```bash
pip install -r backend/requirements.txt
```

| 包 | 版本 | 用途 |
|---|---|---|
| `fastapi` | 0.115.6 | Web 框架，自带 OpenAPI 文档 |
| `uvicorn[standard]` | 0.34.0 | ASGI 服务器 |
| `SQLAlchemy` | 2.0.36 | ORM（2.0 声明式风格） |
| `Pydantic` | 2.10.4 | 请求校验与序列化 |
| `PyMySQL` | 1.1.1 | MySQL 驱动 |
| `python-jose[cryptography]` | 3.3.0 | JWT 签发与校验（HS256） |
| `passlib[bcrypt]` | 1.7.4 | 密码哈希 |
| `bcrypt` | **4.0.1** | ⚠️ 必须锁这个版本，见下方说明 |
| `python-dotenv` | 1.0.1 | 读取 `.env` |
| `openpyxl` | 3.1.5 | Excel 导入导出 |
| `python-multipart` | 0.0.20 | ⚠️ FastAPI 处理文件上传必需，缺失会导致**应用启动即报错** |

**关于 bcrypt 版本锁定**：`bcrypt` 4.1+ 移除了 `__about__` 属性，而 `passlib` 1.7.4 依赖它读取版本号，会导致运行时报 `AttributeError`。所以必须锁 `4.0.1`。

**关于 python-multipart**：它不在 FastAPI 的默认依赖里，但 `UploadFile` / `Form` 需要它。漏装的话 `uvicorn` 一启动就抛 `RuntimeError: Form data requires "python-multipart" to be installed`。

### 1.4 数据库

- **生产/正常开发**：MySQL 8.0+，库名 `warehouse_erp`，字符集 `utf8mb4`
- 建表脚本：`sql/schema.sql`（19 张表，**唯一真源**）
- 初始化数据：`sql/init_data.sql`（幂等，可重复执行）

**存量数据升级（已发货订单刷成已完成）**

改造后仓储发货即完成，状态 40「已发货」不再产生。若库里还留有改造前的 40 订单，执行下面这条语句把它们刷成 50「已完成」（`finished_at` 取原发货时间）：

```sql
UPDATE sales_order
SET status = 50,
    finished_at = COALESCE(finished_at, shipped_at, NOW())
WHERE status = 40;
```

不执行的话，这些历史订单在页面上会显示为「未知状态」。

## 二、启动方式

### 方式 A：Docker 起数据库（推荐）

最省事，不用在本机装 MySQL。

```bash
# 1. 在项目根目录启动 MySQL 容器
docker compose up -d

# 2. 确认容器健康（等状态变成 healthy）
docker compose ps

# 3. 确认初始化脚本已执行（能看到建表和插数据日志）
docker compose logs mysql | tail -30
```

容器首次启动会自动执行 `sql/schema.sql` 和 `sql/init_data.sql`，所以**不需要**再手动建表。

然后跳到「步骤 2 · 启动后端」。

### 方式 B：本地已有 MySQL

```bash
# 建库建表 + 灌初始化数据
mysql -uroot -p < sql/schema.sql
mysql -uroot -p warehouse_erp < sql/init_data.sql
```

### 方式 C：无 MySQL 的开发模式（SQLite）

**仅用于快速看效果或跑测试，不要用于生产。**

本机没有 MySQL、也没有 Docker 时可以用这招。缺点是 SQLite **不支持 `SELECT ... FOR UPDATE`**（SQLAlchemy 会静默忽略），所以**并发行锁不生效**，超卖防护会失效。

```bash
cd backend

# 1. 先建好库和表（用测试脚本自动建，或手动跑一次冒烟测试）
python tests/smoke_test.py

# 2. 用 SQLite 文件启动后端（用环境变量覆盖 .env，不改文件）
DATABASE_URL="sqlite:///$(pwd)/smoke_test.db" \
  uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

> 之所以要先跑一次 `tests/smoke_test.py`，是因为它内置了让 SQLite 认识 `TINYINT` / `BigInteger` 的编译补丁——直接对空 SQLite 文件跑 `create_tables.py` 会报类型错误。脚本会把表和初始化数据都准备好。

### 步骤 2 · 启动后端

```bash
cd backend

# 1. 创建并激活虚拟环境
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

# 2. 安装依赖
pip install -r requirements.txt

# 3. 配置环境变量
cp .env.example .env
# 按需修改 .env，默认连接 root/root@localhost:3306/warehouse_erp

# 4. 建表（二选一，两条路径产物不同，请只选一条）
#    路径 A（推荐）：走方式 A 的 Docker，或手动执行 sql/schema.sql
#                    —— 唯一真源，含全部索引，不含外键约束
#    路径 B（本地快速开发）：python create_tables.py
#                    —— 由 ORM 生成，会额外带外键约束，但缺少部分索引
#    已经走了路径 A 就跳过这步
python create_tables.py

# 5. 写入初始化数据（幂等，可重复执行）
python init_data.py

# 6. 启动
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

### 步骤 3 · 启动前端

```bash
cd frontend
npm install
npm run dev
```

## 三、验证启动成功

### 3.1 冒烟测试（推荐）

`backend/tests/smoke_test.py` 是端到端测试，**不需要 MySQL，也不需要先启动后端**——它自己建库灌数据，再用 FastAPI 的 TestClient 直接打接口。

```bash
cd backend
python tests/smoke_test.py
```

全部正常时末尾会输出：

```
通过 53 项，失败 0 项
```

它覆盖：认证、基础数据 CRUD 与筛选、运营下单、接单预留、备货、发货实扣、出库单生成、库存流水、发货即完成、状态机拦截、权限校验、库存不足拦截、采购全链路、Excel 导出。

> 局限：SQLite 不支持行锁，所以**并发场景测不了**，那部分要真实 MySQL。

### 3.2 手动验证

```bash
# 后端健康检查
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8000/docs
# 期望 200

# 登录（应返回 code=0 和 access_token）
curl -s -X POST http://localhost:8000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}'

# 前端
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:5173
# 期望 200
```

### 3.3 业务链路验证

按角色走一遍完整流程：

1. `operator1` 登录 → 新建订单 → 记下订单号
2. `warehouse1` 登录 → 待接单 → 接单（选仓库）→ 此时库存「预留量」应增加
3. `warehouse1` → 备货中 → 发货（填物流单号）→ 此时库存「库存量」应减少、预留量归零，并生成出库单
4. `operator1` → 我的订单 → 状态直接变为「已完成」，能看到物流单号与完成时间，无需再点确认

## 四、常见问题

### 端口被占用

```bash
lsof -i :8000     # 后端
lsof -i :5173     # 前端
lsof -i :3306     # 数据库
kill -9 <PID>     # 杀掉占用进程
```

如果 5173 被占，Vite 会自动换到 5174，但**后端 CORS 只放行了 5173**，会报跨域错误。要么关掉占用进程，要么把新端口加进 `backend/.env` 的 `CORS_ORIGINS`。

### MySQL 连接失败

1. 确认服务在跑：`docker compose ps` 或 `mysqladmin -uroot -p ping`
2. 确认 `.env` 里的 `DATABASE_URL` 用户名密码端口正确
3. 确认库已建：`mysql -uroot -p -e "SHOW DATABASES LIKE 'warehouse_erp'"`
4. 打开 SQL 日志排查：把 `.env` 的 `DB_ECHO` 设为 `true`

### 登录提示密码错误

按 `docker compose up -d` 启动的，密码一定是 `admin123`。如果不对，说明初始化数据没灌进去或哈希有问题：

```bash
cd backend
python init_data.py     # 幂等，会把三个账号的密码重置为 admin123
```

### `npm install` 慢

```bash
npm config set registry https://registry.npmmirror.com    # 永久切换
npm config get registry                                    # 查看当前源
```

### 后端启动报 `Form data requires "python-multipart"`

依赖没装全：

```bash
pip install python-multipart==0.0.20
```

### 前端 build 报 `NODE_OPTIONS` 相关错误

某些环境注入了不兼容的 `NODE_OPTIONS`，清掉再跑：

```bash
unset NODE_OPTIONS && npm run build
```

### 想重置数据库

```bash
# Docker 方式：删掉数据卷重来（会丢失所有数据）
docker compose down -v && docker compose up -d

# 手动方式：重新执行建表和初始化脚本
mysql -uroot -p < sql/schema.sql
mysql -uroot -p warehouse_erp < sql/init_data.sql
```
